# 聪明钱板块 · 立项书（v0.1，2026-11-15）

状态：**立项 / 框架阶段（S0）**。大叔 11-15 定：先立项做框架，**暂不开发网站**。本文件定稿前不写采集代码、不出页面；
`alpha/sources.json` 里的 `site_smartmoney` 保持 planned。

依据：大叔与 Codex 的方案讨论（2026-11-15）+ 本站现有规则（只给数据和过程、拿不到的标「待接入」、没验证的不能当信号）。

## 一、定位

**可核验地址组的链上行为追踪，不是钱包排行榜。**

本站已有「环境」（宏观 L1–L4、日历）、「赛道」（发射台、AI Agent、RWA）、「标的」（龙头选币、Alpha）三层，缺的是「谁在参与、钱往哪走」。
这个板块补的是一条**资金行为证据链**：登记过的地址组做了什么 → 每一步的交易哈希 → 后来发生了什么。

只回答三个问题：

1. 最近哪些**已登记、证据可查**的地址组在建仓、减仓、加 / 撤流动性？
2. 钱流向哪些代币、协议、赛道、链？
3. 这次是单个主体的动作，还是多个**互不相关**的主体同步发生？

## 二、红线

- **不叫任何地址「聪明」**。页面板块名可以叫「聪明钱」，但每个地址只挂身份类型 + 证据等级，「聪明」是待验证的假设（见第七节），不是标签。
- 不给收益率排名、不做全市场钱包榜、不出「跟单」「买入提示」，不写买卖 / 仓位 / 止损（和全站一致）。
- **不对自然人做身份认定**：个人钱包只有本人公开认领（推文 / 官网 / ENS 且能对上）才写名字，否则只写行为标签和发现渠道；不收人肉搜索、泄露数据、第三方猜测标签。
- 第三方标签（Arkham、Nansen、GMGN、链上浏览器名牌）只作线索，不作证据；CoinMarketCap data-api 不用（全站规则）。
- 数据缺失 = U，不当 0；估值缺价格时只写数量，不补近似价。
- 写入即冻结：地址目录、事件流、每日快照只追加；登记错了用「更正」追加一条，不回改历史（同宏观日志、Alpha 台账）。

## 三、核心对象（数据模型）

| 对象 | 是什么 | 关键字段 |
|---|---|---|
| 主体 entity | 一个地址组 = 判定为同一控制方的一组地址 | id、显示名（只在可公开时有）、身份类型、发现渠道、证据等级、登记日、核验日、状态（候选 / 在册 / 停用） |
| 地址 address | 主体下的单个地址 | 链、地址、归入主体的依据（资金同源 / 官方披露 / 本人认领）、首次链上活动日 |
| 证据 evidence | 每条登记、每次归并都要有 | 类型（官方披露 / 链上关系 / 本人认领 / 行为统计）、链接或交易哈希、核验人、核验日 |
| 事件 event | 一次行为 | 主体、地址、链、类型（见第五节）、代币合约、数量、估值 USD + 价格来源（可为 U）、交易哈希、区块时间（UTC）、首次抓到时间 |
| 快照 snapshot | 每日 UTC 收盘后主体持仓 | 主体 × 代币 → 数量、估值；只追加 |

身份类型（**身份和行为分开**，一个主体一个身份、可多个行为标签）：

- 身份：机构 / 基金（官方披露）· 项目财库 / 团队（官方披露）· 做市 / LP（官方披露或合约关系）· 个人（本人认领）· 未知身份（只靠行为发现）。
- 行为标签（统计出来、每月重算、带版本）：早期参与者 · 持续增持者 · 流动性提供者 · 高频 / 机器人特征。

证据等级（沿用全站 E 级写法）：

- **E1** 一手披露：官方文档 / 公告 / 合约源码 / 本人签名认领，链接可打开。
- **E2** 链上可复现：按写死的规则从链上数据算出来（资金同源、行为统计），任何人拿同样的数据能重算。
- **E3** 二手线索：第三方标签、媒体报道、推特爆料。**E3 只能进候选，不进在册。**

## 四、入选与排除

**三个发现渠道**（每个主体记它从哪来，战绩分开统计）：

- **A 公开身份**：官方披露的机构 / 财库 / 做市地址。用途是看「谁在动」，不是看「谁聪明」。
- **B 行为发现**：从本站已有的样本回溯——Alpha 案例库、龙头选币观测池、发射台毕业币——找「在 ≥ 2 个互不相关的案例里，早期进场（规则写死，例如上线后 N 天内、价格未涨过 X 倍前）且持有 ≥ M 天」的地址。
  N / X / M 在 S2 开跑前写进本文件，跑完不改；发现期和检验期分开（见第七节）。
- **C 人工线索**：大叔推特看到的地址、Codex / Grok 交的线索，先进候选，按 A 或 B 的标准核过才在册。

**一律排除**（规则 + 名单，名单放 `smartmoney/exclude.json`）：交易所热 / 冷钱包与充值地址、DEX 路由 / 聚合器、跨链桥、MEV / 夹子机器人、
代币合约与流动性池本身、发射台曲线合约、销毁地址、项目方部署者（项目财库单列为 A 渠道身份，不算「参与者」）。

**多钱包归并**：只用可复现的关系——同一出资地址在登记前首笔注资、地址间直接互转且无第三方、官方同时披露。归并依据写进证据；拿不准不并。

## 五、事件口径

| 事件 | 判定 |
|---|---|
| 新建仓 | 主体此前持仓为 0（或 < 阈值），本次买入 / 转入后 > 阈值 |
| 追加 / 减仓 | 已有持仓，净增 / 净减超过阈值（按数量比例，不按金额） |
| 清仓 | 持仓降到阈值以下 |
| 加 LP / 撤 LP | 和登记过的池子 / 头寸管理合约交互 |
| 转入交易所 | 转到排除名单里的交易所地址（只记，不推断卖出） |
| 跨链 | 和桥合约交互，两边都登记时配对 |
| 内部划转 | 同主体地址之间——**不算事件**，只进地址详情 |

「真实交易 vs 转账」：经过 DEX 池子 / 路由且对价资产同笔成交的才算买卖；单纯转入转出记为转账，不进净流入。
同步度：同一代币在 72 小时内 ≥ k 个**不同主体**同向（k 在 S3 定，主体之间若有归并疑点不算两个）。

## 六、读数（页面以后展示的东西，先定口径）

1. 资金总览：1 / 7 / 30 天净流入、新建仓数、清仓数、活跃主体数、同步事件数。
2. 代币 / 协议视角：进出主体数、首次被观察到的时间、最近一次行为、在册主体持仓占流通量（拿得到流通量才算）。
3. 主体详情：持仓变化、事件时间线、持有时长、重复参与过的项目。
4. 覆盖说明：在册主体数、各链覆盖、估值缺失比例、数据日——和全站数据状态同一格式。

## 七、要验证的假设（「聪明」只能由这里回答）

- **H1**（B 渠道的价值）：B 渠道主体的「新建仓」之后 30 / 90 天，该代币相对山寨等权篮子（宏观页同一个篮子）有超额。
- **H2**（同步的价值）：同步事件比单主体事件之后的超额更大。
- **H3**（标签稳定性）：行为标签按月重算，下个月保持率 ≥ 多少才算稳定。

方法（开跑前写死，跑完不改，同核心选币评分研究）：发现期选地址、检验期只看样本外；超额相对篮子；最少事件数（例如 ≥ 30 个独立主体-代币对）才判；
通过 / 证伪 / 未通过三档。**H1 通过前，页面不出「信号」字样、不按任何分数排序，只摆行为和证据。**
