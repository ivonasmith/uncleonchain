# 事件日历 · 网站接入说明

和 L2、L3、L4 是同一套做法：一个脚本每天跑一次，输出 `cal_latest.json`；前端只读它。页面怎么摆、文案怎么写，见项目文档《日历网页数据维度规格》。

## 1. 文件

| 文件 | 作用 |
|---|---|
| `cal_daily.py` | 每天生成 `cal_latest.json`：BTC 分区（检验过的事件 + 检验结论 + 用法）、Web3 分区（聚合 Luma、CryptoEvents、IndustryEvents、Web3Voyager、CoinMarketCal、Coindar）、首页“未来 7 天” |
| `btc_events.csv` | 美联储议息（美东 14:00）、CPI 和非农（美东 08:30）日期，录入到 2027-12，来源是美联储和 BLS 官网。季度期权交割按规则自动算 |
| `unlocks.csv` | 代币解锁人工核对表：每条必须有出处，拿不到的数量/价值留空（页面写「数量待核」）。每周日更新；超过 10 天没更新，`data_status.notes` 会提醒。CoinMarketCal / Coindar 接入 key 后，分类为「解锁」的事件会自动并入 |
| `ev_stats.json` | 事件检验结果（2022 年以来），文案里的倍数都从这里来 |
| `cache/`（运行后生成） | 各站上次成功的结果、详情页缓存；某站当天失败时用上次结果 |
| `requirements.txt` | requests、beautifulsoup4 |
| `.github/workflows/cal-daily.yml` | 每天 UTC 00:37（北京 08:37）运行，结果提交回仓库 |

## 2. 接入步骤

1. 本文件夹放进仓库的 `cal/` 目录；workflow 放到 `.github/workflows/`；workflow 已按仓库现行写法配好（输出 `data/cal/`、缓存 `cal/cache` 走 actions/cache、共用 `daily-pipeline` 并发组、跑完重出网站）。
2. 可选：Secrets 里加 `COINMARKETCAL_KEY`、`COINDAR_KEY`（两家都是免费 key），代币事件才会有数据；没有也能运行，只是只有会议。
3. 手动跑一次 workflow，检查 `data_status.detail` 每个站是 `ok（N 条）`。某个站 0 条或失败，说明它改版了，按第 3 节修解析。
4. 按规格新增“事件日历”页面、首页“未来 7 天”卡、宏观仪表盘一行提示。

## 3. 维护

- `btc_events.csv` 录入到 2027-12。剩余不到 90 天时，`data_status.notes` 会提醒补下一年的日期。
- 网页站（CryptoEvents、IndustryEvents、Web3Voyager）的解析方式：先在列表页找活动详情链接，再读详情页里的 schema.org Event；没有就从卡片文字里认日期。站点改版导致 0 条时，改 `src_*` 函数里的链接正则。Luma 用的是它自己的公开接口 `api.lu.ma/discover/category/get-page?slug=crypto`。
- 本地测试：`CAL_OFFLINE=1 CAL_TODAY=2026-11-05 python cal_daily.py`。

## 3.1 代币解锁 Tab（2026-10-25）

页面顺序：比特币大事件 | 代币解锁 | Web3 行业动向。数据 = `unlocks.csv` + 数据源里分类为「解锁」的事件，输出 `cal_latest.json` 的 `unlocks` 段（Web3 Tab 不再重复列解锁）。
「重要」线：单次价值 ≥ 2,000 万美元，或占流通量 ≥ 2%，或属于 `WATCH`（热币分析跟踪的 21 个币），或数据源标为热门。改线在 `cal_daily.py` 顶部。
DefiLlama 的解锁接口是付费的（2026-10-25 实测返回 402），不用。

## 4. 不要做的事

- 不要把 Web3 事件和 BTC 事件混在同一个列表或同一种徽章里。
- 不要在 BTC 事件旁边写涨跌预测。检验结论是：波动会放大，方向不可预测。
- 不要改 `ev_stats.json` 里的数字；它们来自研究脚本。
