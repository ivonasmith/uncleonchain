# 关键人名单 · 任务包（2026-11-15）

目的：Alpha 雷达的线索来源改成「关键人 + 本站板块」为主。关键人不是粉丝多的人，是**在历史案例上公开讲得早、讲得具体、而且不止一次**的人。
名单要可核对（每条带原帖链接和时间），也要记他们讲错的（保留分母）。建好后写进 `alpha/sources.json`，每人单列一行记战绩，连续三个月没有有效发现的降级。

## 谁来做

| 步骤 | 用谁 | 为什么 |
|---|---|---|
| S1 找候选 | **Grok**（会话框，手动发） | 关键人的原帖在 X 上，Grok 能直接搜 X 的历史帖 |
| S2 核对 | **Codex** | 逐条打开链接核时间、去重、算命中，交 JSON |
| S3 并入 | Claude | 写进来源台账，网站「雷达」页显示 |

Gemini Pro 这个任务用不上，先不用开。Grok API 也不用：会话框够用，案例分 3 批发就行。

## S2 · 发给 Codex 的提示词（附上 Grok 的原始回答）

```
附件是 Grok 按案例列出的「最早公开讲过这个项目的 X 账号」。请逐条核对并整理成 JSON，文件名 sources_people.json。

核对：
1. 每个链接能否打开、发帖时间和 Grok 说的是否一致（不一致以原帖为准，打不开的标 unverified，不要删）。
2. 帖子内容是否真的在讲机制 / 玩法 / 数据（substantive = true / false）。
3. 去重：转发、引用同一来源的只留最早一条。
4. 对出现在 2 个以上案例的账号，再查它近 12 个月公开推过、后来明显失败的项目（最多 5 个，带链接），记进 misses。查不到写空数组，不要猜。

交付格式（JSON 数组，每个账号一项）：
{
  "handle": "@xxx", "platform": "x", "role": "开发者|研究员|基金|交易员|KOL|媒体|不确定",
  "disclosed_interest": "未见披露 或 具体披露内容",
  "hits": [{"case": "案例 id", "url": "原帖链接", "posted_utc": "2020-09-17", "lead_days": -3, "substantive": true, "what": "一句话", "verified": true}],
  "misses": [{"project": "名称", "url": "原帖链接", "posted_utc": "日期", "what": "一句话"}],
  "still_active": true, "checked_utc": "核对时间", "notes": "需要说明的"
}
lead_days = 发帖日 − 起点日（负数 = 早于起点）。只做事实核对，不写买卖建议，不评价账号好坏。
```

## 交回之后

把 `sources_people.json` 放进 `alpha/review/`（或直接发给 Claude）。入选标准先定成：**2 个以上案例有已核实、讲实质内容、早于起点后 7 天的帖子**。入选的写进 `alpha/sources.json`（type = people），之后他们讲的新项目登记为线索，战绩从登记日起算。

## 已知局限（写在前面，免得误读名单）

- 案例库 25 个里大多是后来成功的：按「讲对过」选人有幸存者偏差，所以 S2 要查 misses。
- 2020 年以前的帖子在 X 上搜索不全，早期案例（BTC、ETH、CryptoPunks）大概率查不到，名单会偏向 2020 年以后。
- Grok 给的链接和时间可能出错，所以必须过 S2，没核对的不入选。
- 盯这些账号的新帖目前没有自动办法（X 没有免费接口）：先靠 Codex / Grok 每周查一次名单里的账号，或者大叔看到了登记手动线索。
