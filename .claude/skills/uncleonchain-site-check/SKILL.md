# 链上大叔研究台 · 推送前自查

这个 skill 把 CLAUDE.md 和 `docs/` 里的几条规矩变成一套固定动作。改页面后按顺序做完，别跳步。
规范原文：`docs/表达规范.md`（怎么说话）、`docs/SEO规范.md`（页面怎么被找到）、`pipeline/RUNBOOK.md`（发射台日更，不在本 skill 范围）。

## 0. 先确认改了什么

- 改的是哪些板块、哪些页面？记下来，自查时重点看这些页。
- 只改了文案 / 配置（`config/`、`content/`）还是改了代码（`pipeline/`、`l*/`、`web/`）？两种都要跑完整流程，不要只跑一半。

## 1. 本地出网站

仓库根目录执行。两步缺一不可：

```bash
export LP_DATA=$PWD/data LP_OUT=$PWD/build
python3 pipeline/出看板.py
python3 pipeline/出网站.py
```

- 第一步产出 `build/网站素材.json`，第二步才能跑（直接跑 出网站.py 会报「没找到网站素材.json」）。
- 约 20 秒。末尾会打印「SEO 检查：N 页，M 条警告」，**基线是 0 条**。新增警告要修掉，不要带着推。
- 出网站会改动仓库里的 `site/`。提交前：`git checkout -- site/data/launchpad`（CLAUDE.md 的规矩，否则会把本地生成的发射台文件提进去）。
- **不要用 `git stash`**（仓库里出过丢改动的事）。

## 2. 表达规范检查（文案）

```bash
python3 .claude/skills/uncleonchain-site-check/scripts/expr_check.py site
python3 .claude/skills/uncleonchain-site-check/scripts/expr_check.py site --loose   # 多看弱指令词
```

脚本会列出三类可疑处，**由你判断，脚本不替人下结论**：

- **【强】指令词**：不追高、加仓、减仓、风险预算、止损、止盈、抄底、不开新空……出现在 description 或非豁免页正文，就要改。
  - 豁免页（方法论、口径、日志、更正记录、复盘、报告、文章）里的引用可以留，但要标「研究框架原文 · 作者自用规则」。
  - 「不作抄底信号」「不写买入、卖出」这种否定句 / 免责声明是允许的，脚本已经跳过大部分；列举式免责声明可以人工放过。
- **【行话】**：正文开头 300 字里有 P90、σ、z 值、STH、闸门 这类词，第一句要改成大白话（表达规范 §3）。行话可以放到 ⓘ 悬浮说明或 `.term` 里。
- **【弱】**（加 `--loose`）：买入、卖出、建仓、建议、应该。很多是产品说明里的正常用语，只有指向读者的动作才改。

脚本退出码为 1 = 有强命中，推送前必须清零或逐条说明为什么保留。

### 改写方法（表达规范 §2）

把「做什么」换成「现在是什么 + 过去怎样」，并带分母。

| 原句（指令） | 改成（状态 / 历史） |
|---|---|
| 宏观逆风，节奏上不追高，风险预算打七折 | 宏观逆风（实际利率急升，又碰上信用利差走阔） |
| 资金费率转负，空头拥挤：短期不追空 | 资金费率转负，空头拥挤（已验证：过去 31 次，之后 30 天上涨 74%） |
| 不据此抄底 | 熊市里这条信号偏弱（历史 8 次只有一半上涨） |

- 每个板块第一句是状态句，大白话。
- 写历史数字必须带次数（分母）和检验等级；没检验的标「假设级」。
- 不写 买入 / 卖出 / 加仓 / 减仓 / 仓位 / 止损 / 止盈 / 抄底 / 追高 / 「可以 / 应该 / 建议 / 别」+ 动作。

## 3. SEO 检查

- 出网站末尾的「SEO 检查」就是 `pipeline/seo_check.py`，必须 0 条警告。
- 新页面一律走 `出网站.page()`，不手写 `<head>`。
- title 格式：`<页面主题> · 链上大叔研究台`，英文 `… · Uncle Onchain`。单币 / 单协议页带日期。
- description：写「这页是什么、有哪些数据」，**不写当天结论，不写任何操作性措辞**（追高 / 抄底 / 仓位 / 止损 / 买卖）。
  中文 20～150 字，英文 40～220 字符。脚本会一并检查。
- 首屏关键数字要写进 HTML，不能只有「读取中…」（`seo_check` 会报空壳页）。
- 实体级内容要有真实路径（`/core/<币>/`、`/alpha/<slug>/`），不要只用 `#…`。
- 英文没翻完的页要放 `ZH_ONLY`，`page()` 会自动 noindex。

## 4. 截图自查（手机 + 桌面）

```bash
node .claude/skills/uncleonchain-site-check/scripts/shots.js site /tmp/claude-0/shots
```

截 13 个关键页（首页、宏观、核心、Alpha、发射台、涨跌腿、日历、聪明钱、AI Agent、RWA、日志、英文首页、英文宏观）的桌面（1440 宽，2x）和手机（390 宽）两版。
同时检查：

- **手机横向溢出**：报出溢出像素和最宽元素。这是真问题，必须修。
- **仍有「读取中…」占位**：说明首屏数字没写进 HTML。
- **本站 404 和 JS 报错**：外部字体 / CDN 加载失败是沙盒代理的噪声，脚本已过滤。

然后用 Read 工具打开关键截图（`/tmp/claude-0/shots/<页>_desk.png` 等）亲眼看一遍，重点看：
首屏第一句是不是大白话、有没有指令词、卡片有没有空白或错位。自查只看脚本的结论不够，要看图。

只指定几页：`SHOT_PAGES="/,/macro/" node …shots.js site <输出目录>`。

## 5. 提交

1. 自查项全部通过（或逐条说明为什么保留）。
2. `git checkout -- site/data/launchpad`。
3. 只提交本次改动相关的文件，commit message 用中文写清楚改了什么。
4. 按仓库的 Git 规则推送（CLAUDE.md 写的是推 `main`，会话的分支规则以会话指示为准，两者冲突时先问大叔）。

## 已知待修（2026-11-16 首次自查结果）

这些是 skill 首次运行发现的真问题，改之前先确认是不是已经修过（重新跑一遍脚本）：

- 首页「解读」一句写着「节奏上不追高，风险预算打七折」「风险预算照常」，违反表达规范 §2，来源是 `config/composite.json` / `pipeline/综合研判.py` 的拼接。
- 手机宽度横向溢出：首页 188px、聪明钱页 334px、英文首页 204px。
- 首页首屏「L3 · STH 成本下方」用了 STH 行话（表达规范 §3）。
- 英文页的指令词扫描暂无命中，但 E8（各板块首屏第一句改成状态句）还没做完，改版时要逐板块看。

## 红线（任何情况都不许）

- 不编数字，拿不到真实数据的标「待接入」。
- 不写买卖建议，不给仓位、止损、止盈、挂单。
- 不改已冻结的历史日志（`data/解读日志/` 写入即冻结）；规则改动写进 `RULE_CHANGES` 并在更正记录里说明。
- 不在 SEO 文案里放操作性措辞，不堆关键词，不做没数据的落地页。
