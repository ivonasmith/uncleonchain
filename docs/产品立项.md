# 链上大叔研究台 · 产品立项书（草案 v0.1，2026-11-28，待大叔确认）

> 状态：**草案**。大叔确认前，本文件里的「计划」都不动网站；确认后改成 v1.0，后续每次改动在文末「版本记录」加一行。

## 1. 产品定义

- **一句话**：个人 web3 链上数据情报终端——用公开、可核对的数据，回答「市场现在处在什么状态、历史上类似状态之后发生过什么」。
- **给谁用**
  1. 大叔本人和大叔的交易程序（读 `/data/status.json`、`leg_latest.json` 等接口；新加坡 19:00 取数、20:00 发推）。
  2. 推特读者：从推文直链进某个板块，看一眼就懂当前状态。
- **不做什么**：不给买卖指令（`docs/表达规范.md`）、不编数字（拿不到的标「待接入」）、不做 0–6 小时打狗、不出钱包榜。

## 2. 板块结构：四个核心 + 支撑层（大叔 11-28 定方向）

### 2.1 四个核心板块

| 核心板块 | 回答的问题 | 现有内容 | 主要缺口 |
|---|---|---|---|
| **宏观仪表盘** /macro/ | BTC 和大盘现在处在周期的哪个位置？短期在哪条腿上？ | 四层框架（L1 流动性 / L2 周期 / L3 筹码 / L4 情绪）、涨跌腿追踪（含换腿过渡期）、综合研判 | 版面信息密度高、首屏不够直观；L1 部分序列待核对 |
| **发射台** /launchpad/ | 链上新币发行热不热，钱在往哪个平台走？ | 发射台矩阵、活动温度、量的质量（存活 / 交易者试点） | 交易者 / 刷量口径待接入 |
| **龙头选币** /core/ | 成熟大币里，谁的基本面和资金在变好？ | 观测池读数、选币规则 v1、评分研究立项（M0–M5）、机制拆解卡 | **单币量化框架（见 §3，新立项）**；评分研究未通过前不排名 |
| **Alpha 雷达** /alpha/ | 还没成熟的新东西里，哪些值得研究？ | 机会看板、综合分 v3、案例库、交易所上币线 | 补证覆盖率；上币线页面未上线 |

### 2.2 支撑层（不占核心导航位，给核心板块供数据、方法和背书）

| 类别 | 现有页面 | 和核心的关系 |
|---|---|---|
| 数据支撑 | 事件日历、聪明钱（立项中）、AI Agent、RWA | 作为 Alpha 雷达 / 龙头选币的数据源，同时保留独立页面 |
| 方法论 | 口径与规则、使用指南、各板块方法页 | 每个核心板块的「怎么算的」统一链到这里 |
| 研究产出 | 分析报告、解读日志、周 / 月复盘 | 核心板块的结论留档 |
| 信任 | 更正记录、更新日志、关于 | 证明数字可核对 |

## 3. 新立项：龙头币量化框架（P1）

- **目标**：像 BTC 的「涨跌腿 + 四层框架」一样，给热门大币各做一套单币状态框架（SOL、ETH、NEAR、ENA 等，每个币的框架不一样）。
- **分工（大叔 11-28 定）**：框架维度由大叔在别处研究、设计好；网站这边只负责上架。上架按 `docs/开发流程.md` 的 C 级流程走：方案卡 → 大叔确认 → 开发 → 预览 → 大叔验收 → 上线。
- **页面**：按新的视觉规范做，位置在框架交付时一起定。初步考虑放在龙头选币下的单币页 `/core/<币>/`，符合 SEO 实体路径规范。
- **网站侧提前准备**：不写指标代码，只在视觉规范里预留「单币详情页模板」（见视觉规范任务包第 3 项）。

## 4. 产品要求（全站，所有板块都要满足）

1. **每个页面首屏第一句是状态**（大白话），然后是条件 + 历史（带分母和检验等级），不出现指令。
2. **数字可核对**：每个读数有来源、有截至时间，口径写在「口径与规则」。
3. **中英双语、深浅主题、手机可用**（390px 宽无横向滚动）。
4. **SEO**：按 `docs/SEO规范.md`。
5. **接口稳定**：大叔交易程序和 hotcoin 读的 json 只能加字段，不能改、删已有字段。
6. **视觉和交互**：按《视觉与交互规范》（待 Gemini 出稿，见 `docs/提示词_视觉规范_Gemini.md`）。规范出来之前，新页面版面必须先给大叔看截图。
