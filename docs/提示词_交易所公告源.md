# 提示词：交易所上币公告源（给 Grok 和 Codex，整段复制）

---

你在帮「链上大叔研究台」（uncleonchain.com）接交易所的**上币公告**。目标：10 家交易所，每家找到**程序能直接读**的公告来源，让我们记录每次上币的公告时间、计划开盘时间、交易对。

交易所：Binance（已接好，不用查）、OKX、Bybit、Bitget、Coinbase、Upbit、Bithumb、Kraken、Gate、MEXC。

## 每家要回答的 6 件事

1. **官方公告列表**：上新 / 上币栏目的网页地址，以及它背后的数据接口（JSON 或 RSS）。要能不登录、不带 key 直接请求。给出完整 URL 和一次真实请求的返回样例（前 2 条）。
2. **字段**：返回里有没有 标题、发布时间（什么时区 / 格式）、正文或正文链接。计划开盘时间和交易对在哪（标题里 / 正文里 / 单独字段），给一条真实例子。
3. **翻页与历史**：怎么翻页，最早能翻到什么时候。
4. **限制**：是否按国家拦（美国机房 GitHub Actions 能不能访问）、是否有 Cloudflare 人机验证、频率限制。被拦的话，有没有官方的替代入口（别的域名、RSS、官方 API 文档里的公告接口）。
5. **官方 X 账号**：发上币公告的那个账号的**准确用户名**（例如 Coinbase 的上币在 @CoinbaseAssets，不是 @coinbase）。给最近 3 条上币帖的链接和发帖时间（UTC），并对上同一次上币在官网公告的时间，看谁先。
6. **K 线**：该所现货 1 分钟 K 线的公开接口（不带 key），能取多早的历史，是否按国家拦。

## 第三方聚合源（另列一节）

有没有一个接口能一次给出多家交易所的上币公告（带原始公告链接和时间）。每个候选写：覆盖哪些所、有没有读取接口（不是只有推送）、能不能查历史、价格（只抄官网写的数字）、条款是否允许存档。只列你**实际打开核对过**的。

## 硬规则

- 每条事实带来源链接和核对时间（UTC）。没查到写 `"U"`，不要猜、不要凭记忆写接口地址——**每个接口地址必须是你实际请求成功过的**，把 HTTP 状态码写上。
- 请求失败也要写：哪个地址、什么状态码、返回了什么。
- 时间一律写 UTC，原样记录，不合并（公告时间、计划开盘时间是两个字段）。
- 不写买卖建议，不评价项目。
