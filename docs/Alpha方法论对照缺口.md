## 三、交易所事件（第九节，全节）— **这一条线要做完**

文档要求（原文要点）：
- 分别记录：公告时间、修订时间、计划开盘、首笔实际成交、现货 / 永续、交易对、报价币。
- 「首发 / 跨所扩散 / 同步上市」只限已观测交易所集合，不能说全球首发。
- 多所同一资产事件要聚类，不能把一次行情当多次成功。
- 比较事件前涨幅、首笔冲高、稳定开盘后表现、成交额持续性、回撤、退出容量；30 分钟 / 1 小时 / 4 小时 / 24 小时窗口**成熟后**计算，不用当前行情回填；韩元、USDT、USD 报价不能未换算合并。
- 交易所优先级只决定关注预算，不写进质量分。

现状：
- 只有 Binance 公告标题 + 发布时间，没有计划开盘、首笔成交、交易对、报价币字段。
- 没有任何价格窗口计算，没有多所聚类，没有报价币换算。
- 交易所覆盖：Binance 可接；Bybit、Upbit 探测结论为「可接」但我们在 Actions 环境实测过不通（CloudFront 按国家拦、Cloudflare 人机验证），**需要在 Actions 里重新验证**；OKX、Coinbase 探测为「不可接」。
- 文档附录三 C 列的「官方公告 / API、Binance 历史归档、聚合线索」，目前只用了第一项的一部分。**第三方聚合源（Tokenearly 等）文档明确允许做发现、但事实必须回查官方，我们还没有接任何一家。**

**完成标准**（我来做，Codex 负责查源和核样本）：
1. 至少 Binance 完整链路：公告 → 计划开盘 → 首笔成交（K 线第一根）→ 现货 / 永续 → 30 分钟 / 1 / 4 / 24 小时窗口（成熟后才算）。
2. 其它交易所每家一条验收结论（能否拿到公告、计划开盘、历史 K 线；需要 key 还是要换 IP；样本 ≥ 20 条核过）。
3. 报价币换算（USDT / USDC / BTC / KRW / USD）的日源。
4. 同资产多所聚类，按已观测集合标注「首发 / 跟随」。
5. 网站：交易所事件页 + 上市类机会卡显示窗口读数，未成熟显示「未到期」，缺数据显示「U」。
