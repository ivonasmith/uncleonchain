# 接口约定：发射台板块 → Alpha 雷达（2026-11-15）

大叔 11-15 定：Alpha 机会卡要回答「量从哪来、量是不是真的、激励结束后还剩多少」。发射台类的平台（Montra、Pons、Volta、Ascend、Boxa…）
这些数据**由发射台板块来补**，补进发射台自己的页面，Alpha 只读，不另算一套。这样两个板块一起变好。

## 文件

`data/onchain/平台质量.json`，按 DefiLlama slug（和 `data/发射台矩阵.json` 的 `协议[].slug` 一致）：

```json
{
  "更新UTC": "2026-11-16T03:00:00Z",
  "平台": {
    "montra": {
      "数据日": "2026-11-15",
      "发币": {"1d": 990, "7d": 93000, "口径": "工厂合约当天新铸整数供应量的币（拉链上新台.py），下限", "来源": "链上"},
      "发币人": {"7d": 1234, "口径": "查过交易的不同发币地址，下限", "来源": "链上"},
      "存活": {"批次": "2026-11-08", "发出": 13000, "7天后仍有交易": 210, "市值过10万美元": 6, "口径": "…", "来源": "DexScreener / GeckoTerminal"},
      "交易者": {"1d": null, "7d": null, "前10地址成交占比": null, "口径": "…", "来源": "待接入"},
      "事件": [{"日期": "2026-11-05", "事": "空投积分开放", "出处": "https://…"}]
    }
  }
}
```

规矩（和全站一样）：
- 每个字段带「口径」「来源」。拿不到写 `null`，页面显示「待接入」，**不估、不拿近似值冒充**。
- 第三方统计（Elytrack 之类）可以收，但「来源」写清是谁、标二手；能用链上自己算的优先自己算。
- 只追加历史，不回改；每天一份覆盖「当前」，历史另存 `平台质量_history.json`（可选）。

## 字段优先级（发射台板块按这个顺序接）

| # | 字段 | 现状 | 建议做法 |
|---|---|---|---|
| 1 | 每天 / 7 天发币数、发币人数 | **已有**：`data/onchain/<链>.json` 按工厂合约逐日记了「新币」「发币人」 | 把工厂合约对到 DefiLlama slug（`config/launchpad_factories.json` 已有部分名单），按平台汇总写进上面的文件 |
| 2 | 存活：某天发的币，7 天后还有多少在交易、多少市值过 10 万美元 | 没有 | 每天从「新币」样本里取一批地址，7 天后用 DexScreener `tokens/{地址,地址…}`（一次最多 30 个，免费）查流动性 / 成交 / 市值 |
| 3 | 关键事件（积分开放 / 结束、主网上线、发币、费率改动） | 平台介绍里零散有 | 人工 / Codex 登记，必须带日期和官方出处 |
| 4 | 交易者数、前 10 地址成交占比、同一主体多钱包 | 没有 | 要扫交易事件，每条链不一样，可能要付费索引；先标待接入，挑 1–2 个平台试 |

## Alpha 这边怎么用

- 发射台类的机会卡（类目 Launchpad 或来自发射台矩阵）读这个文件，放在「量的质量」一层：发币数、发币人、存活率、交易者，缺的显示「待接入」。
- 「事件」画在协议收入走势图上。
- 文件不存在或平台没有条目：整层显示「发射台板块还没覆盖」，不报错。
