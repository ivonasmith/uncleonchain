# 开发流程（草案 v0.1，2026-11-28，待大叔确认）

> 起因：11-28「换腿过渡期」新版块（新一节页面 + 图 + 表 + 导航项）没给大叔看方案和截图就直接上线了。从这份流程确认起，所有会话（Claude / Codex）都按这里走。

## 1. 改动分级：决定要不要先问大叔

| 级别 | 什么算 | 流程 |
|---|---|---|
| **A 日常** | 日更数据、修 bug（不改版面）、数据源修复、补证并入 | 直接上线，在当天的回复里说一句 |
| **B 口径** | 改统计口径、阈值、文案措辞、接口加字段（页面不变） | 先说明改什么、为什么，**大叔点头再上**；上线后更新日志和更正记录各记一条 |
| **C 产品** | 新页面、新板块、新图表 / 表格、改版面、改交互、改导航 | **必须过两道确认**：G1 方案确认 + G3 预览验收，缺一不上线 |

拿不准属于哪级，就按高一级走。

## 2. C 级改动的流程

| 阶段 | 谁做 | 产出 | 过关条件 |
|---|---|---|---|
| G0 需求 | 大叔 | 一句话需求，或需求文档（像换腿过渡期那份就很好） | — |
| **G1 方案** | Claude | 方案卡（模板见 §3）：放在哪个页面的什么位置、有哪些模块、交互怎么走、首屏文案、数据字段。附**草图或低保真截图** | **大叔确认** |
| G2 开发 | Claude | 代码，推开发分支（不推 main） | 自检：selftest、出网站、SEO 0 警告、禁用词扫描 |
| **G3 预览** | Claude | 中英文 × 桌面 / 手机四张截图，发给大叔；能开预览链接就给链接 | **大叔验收**，提的修改改完再看一轮 |
| G4 上线 | Claude | 合并 main、更新日志一条、口径页同步 | — |
| G5 回看 | Claude | 上线后核对线上页面和数据（Actions 跑完后） | 有问题当天说 |

**数据计算和页面分开验收**：数字能先算、先核对（比如验收基准），但页面要等 G3 过了才上线。

## 3. 方案卡模板（G1 用）

```
需求：一句话
放在哪：页面 / 位置（截图标出来）
模块：① … ② …
首屏第一句（中 / 英）：…
交互：点哪里、展开什么、切换什么
数据：读哪个文件的哪些字段，新加什么字段
不做什么：…
待大叔决定：…
```
