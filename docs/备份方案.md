# 备份与灾难恢复方案（2026-11-15 起草）

目标：GitHub、Notion、Cloudflare 任何一家出故障或封号，**数据不丢、一天内网站能重新上线**。
原则：每样不可再生的东西 ≥ 2 份，放在**不同公司、不同账号**；其中一份在大叔手里离线保存。

## 1. 第一份：异地自动备份（每天 / 每周自动跑）

| 编号 | 做什么 | 频率 | 去哪 | 状态 |
|---|---|---|---|---|
| B1 | `git push --mirror` 整个仓库（全部分支、全部历史） | 每天，日更完成后 | Codeberg 或 GitLab **私有**仓库 | 待做（需大叔注册账号、给 token） |
| B2 | Notion API 导出全部板块入口页和数据库（Markdown + CSV，附件下载），**按板块分目录**（一个入口页一个目录） | 每周 | 单独的**私有**备份仓库（**不能进主仓库，主仓库是公开的**） | 待做（需 Notion 集成 token） |
| B3 | `git bundle` + Notion 导出包 + 最新 Agent ID checkpoint，用 restic 加密 | 每周 | 对象存储：Backblaze B2 或 AWS S3（**不用 Cloudflare R2**，网站已在 Cloudflare，别把鸡蛋放一个篮子） | 待做（需存储账号 + key） |

注意：B1～B3 如果只在 GitHub Actions 上跑，GitHub 封号时任务也停了。已经推出去的备份不受影响，最多丢最后一天；
所以第二份（§2）要在 GitHub 之外跑。

restic 仓库密码不能只存在 GitHub Secrets 里（见 §3）。

### 1.1 Notion 的组织规则（大叔 11-15 定）

- **每个板块一个独立的顶层入口页**（和「Alpha 雷达」一样），这个板块的数据库、周复盘、备份附件都放在自己入口页下面，**不挂在任何别的文档下面**，好找。
- 新板块要在 Notion 建东西时：先建本板块入口页，登记到下表，再在入口页 ··· → 连接 里加上同步 / 备份用的集成。
- 大叔以后会整理归类、删没用的：
  - Notion 里删掉的东西，在 B2 / B3 的历史版本里还在，误删能找回。
  - 移动页面不改页面 ID，同步脚本不受影响；移动后如果同步报 404 / 无权限，在该页 ··· → 连接 里把集成重新加上。
  - 同步脚本写死了数据库 ID 的（如 `alpha/notion_sync.py`），**整个数据库删掉会让同步失败**（不影响日更，只是 Notion 不再更新）；不要了先告诉 Claude 把同步关掉。

## 2. 第二份：大叔手里的离线备份

- 电脑上一个每周定时任务（macOS launchd / Windows 任务计划，脚本由 Claude 写好）：
  `git clone --mirror`（或 fetch 已有镜像）主仓库 + 拉一份 B2 的 Notion 导出 → 同步到移动硬盘。
- 移动硬盘每月拔下来单独放（防勒索软件、防误删同步）。
- 恢复不依赖网络：硬盘上的镜像能直接 `git clone` 出来跑出网站。

## 3. 密钥与账号

1. 所有 key、token、restic 密码存进密码管理器（Bitwarden 或 1Password），**不只存在 GitHub Secrets**（Secrets 读不出来）。
2. **`AGENT_ID_STATE_KEY`、restic 密码、各平台 2FA 恢复码，再抄一份纸质的**，和移动硬盘分开放。
3. GitHub、Notion、Cloudflare、域名注册商、备份平台全部开 2FA；恢复邮箱不要只用一家。
4. **域名注册商和 Cloudflare 分开**：域名放在独立注册商（如 Porkbun / Namecheap），Cloudflare 只管 DNS 和 Pages；
   Cloudflare 出事时去注册商改 NS 即可。
5. 云端环境「uncleonchain」的放行域名清单抄进本文件 §4，环境丢了照着重建。

## 4. 恢复手册

### 4.1 GitHub 不能用
1. 从 Codeberg / GitLab 镜像（或移动硬盘）clone 仓库。
2. 在新平台建仓库，按 §3 的密码管理器把 secrets 填回去。
3. workflow 改成新平台的 CI（GitLab CI / Forgejo Actions），或先在本机跑 `pipeline/跑日更.py --site` 维持日更。
4. Cloudflare Pages 改成从新仓库部署，或直接上传 `site/`。

### 4.2 Cloudflare 不能用
1. 本机或任意 CI 出网站，`site/` 部署到备用托管（Netlify / Vercel / GitHub Pages，事先建好空站）。
2. 去域名注册商把 NS 改到新 DNS，按清单重建记录。
3. `_headers` 的缓存规则按新托管的格式改写。

### 4.3 Notion 不能用
1. 从备份仓库 / 对象存储 / 移动硬盘取最近一次导出（Markdown + CSV）。
2. 导入新工具（Obsidian、新的 Notion 账号或任何 Markdown 工具）。
3. 网站本身不依赖 Notion 运行，`core/core_config.json` 等人工登记已在仓库里。
