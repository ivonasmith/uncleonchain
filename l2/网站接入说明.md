# L2 周期层 · 网站接入说明（交给 Claude Code 照做）

> **uncleonchain 仓库的实际接入（2026-10-08）**：代码在 `l2/`；定时任务 `.github/workflows/l2-daily.yml`（UTC 02:17）输出到 `data/l2/`，
> 出网站时复制到 `site/data/l2/` 并渲染宏观页 L2 段（`pipeline/出网站.py` 的 `l2_section`），只读 json、不做计算；
> UTC 10:20 的日更把当天 L2 状态写进解读日志。缓存 `l2/cache/` 用 actions/cache，不提交。

## 1. 这个文件夹是什么

| 文件 | 作用 |
|---|---|
| `l2_daily.py` | 每天跑一次：从 Coin Metrics 和 bitview.space 取数，算信号，跑状态机，输出 JSON。两个数据源都免费，不需要账号或 API key |
| `l2_signals.py` | 信号和状态机的全部规则。和研究文档《BTC周期层L2研究》§7 是同一份代码，**不要在网站前端重写这些规则** |
| `requirements.txt` | 依赖：pandas、numpy、requests |
| `.github/workflows/l2-daily.yml` | GitHub Actions 定时任务：每天 UTC 02:17（北京时间 10:17）运行，把结果提交回仓库 |
| `output/`（运行后生成） | `l2_latest.json`（今日结论）、`l2_history.json`（近 400 天，画图用） |
| `cache/`（运行后生成） | 上次成功取到的数据；某个数据源当天取不到时用它继续算 |

## 2. 接入步骤

1. 把本文件夹放进网站仓库的 `l2/` 目录。
2. 把 `.github/workflows/l2-daily.yml` 放到仓库根目录的 `.github/workflows/`，并把 `L2_OUT_DIR` 改成网站实际的静态文件目录（例如 Next.js 是 `public/data/l2`，Astro 也是 `public/`）。
3. 在 GitHub 仓库 Settings → Actions → General 里，确认 Workflow permissions 是 “Read and write”。
4. 在 Actions 页面手动点一次 “Run workflow”，确认生成了 `l2_latest.json`。
5. 前端只读取 `l2_latest.json` 和 `l2_history.json` 展示，不做任何计算。

如果网站已经用别的方式定时更新 L1（例如 Vercel Cron），照 L1 的方式跑 `python l2/l2_daily.py` 即可，效果一样。

## 3. `l2_latest.json` 字段

| 字段 | 内容 | 展示建议 |
|---|---|---|
| `data_date` / `updated_utc` | 数据日期 / 运行时间 | 卡片角标 |
| `state.code` | 六个状态之一：`BULL` `BULL_RISK` `BULL_PULLBACK` `BEAR` `BEAR_ZONE` `RECOVERY` | 决定主色 |
| `state.name_zh` / `desc_zh` / `since` / `days` | 状态中文名、一句话解释、从哪天开始、已持续天数 | 主标题：“熊末→牛初（底部已确认）· 第 39 天” |
| `state.previous` | 今天刚切换时，前一个状态的名字；没切换为 null | 有值时加醒目提示“今日状态变化” |
| `state.next_zh` | 这个状态下接下来看什么、什么情况下会切换 | 主卡片底部 |
| `summary_zh` | 已经写好的每日结论全文（多行） | 直接按行显示，不要改写 |
| `cycle` | 距新高回撤、距本轮最低点反弹、距减半天数等 | 小数字行 |
| `valuation` | MVRV、价格/200 周均、盈利供应占比、一年盈亏比、LTH 占比、绿/黑比 | 指标网格 |
| `signals[]` | 14 个信号：`name_zh`、`category`（底部区 / 底部确认 / 顶部风险）、`evidence`（证据等级）、`ref`（研究文档章节）、`note`、`on`（是否亮起）、`changed_today` | 按 category 分三组的列表；亮起的用实心点；`changed_today` 为 true 的加 “今日” 标签；`evidence` 做成小徽章 |
| `levels[]` / `levels_above` / `levels_below` | 13 条关键价位（成本线、均线、价格下限），带离现价的百分比 | 价格梯子：现价居中，上方 3 条、下方 3 条 |
| `data_status.stale` | 有数据源当天没取到时为 true | 为 true 时卡片显示灰色 “数据延迟” 标签 |

`l2_history.json`：每天一条，含 `date`、`state`、`price` 和 7 条成本线，用来画“价格 + 成本线 + 状态背景色”的图。

## 5. 页面上必须有的说明（放在卡片下方小字）

> 规则化状态机，每天按最新链上数据自动判定，不含人工判断。周期样本只有 4 轮，所有结论最高只到“已验证·方向”，不构成投资建议。方法和每条信号的历史检验见研究文档。

## 6. 运行失败怎么办

- 某个数据源当天取不到：脚本会用缓存继续算，并把 `data_status.stale` 设为 true，网站照常显示。
- 整个任务失败：GitHub 会发邮件通知；网站继续显示上一次的 JSON。
- bitview.space 长期停服：把 `L2_BV_BASE` 环境变量指向自建的 Bitcoin Research Kit 实例即可，代码不用改。
